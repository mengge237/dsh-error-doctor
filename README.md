# dsh 错误分类补丁与体检

DSH 的一部分失败被归错类：**403 的额度类回包会先撞上"鉴权失败"那条分支**，界面上只剩一句"API 密钥无效"，原始原因看不见。这里放两样东西：一套**可重放的补丁工具**，和一个**只读体检命令**。

## 先说体检，因为它比补丁有用

```bash
node bin/dsh-error-doctor.mjs        # 退出码 0=已修 / 1=出厂形状 / 2=读不出来
```

为什么需要它：DSH 升级会覆盖安装目录，**补丁是静默消失的** —— 不打日志、不报错，只是回到出厂判断。别拿"最近能用"当证据，跑一次体检才算。

判据的做法值得单说一句，因为它推翻了我自己第一版的实现：最初我用"源码里 403 和额度判定谁先出现"来判，听着合理，实测连错两次。

- 补丁文件自己的注释里写着"…then 403"，静态扫字符串就把已修的产物读成没修；
- 真正的修法之一是把额度判定**放进 403 分支内部**（`if (status === 403) { if (isQuota(...)) return QUOTA; ... }`），文字上 403 在前，语义上已经修好；
- 同一个文件里还有一处 `status === 401 || status === 403`，那是 Files API 的错误构造器，跟分类无关，"取文件里第一个匹配"会直接改错地方。

所以体检的做法是：**把已安装产物里的分类函数抠出来，喂一条真实的 403 额度报文，看它返回什么。** 不猜形状，不认注释，别人打的补丁也照样能认出来。

## 里面有什么

| 文件 | 作用 |
| --- | --- |
| `bin/dsh-error-doctor.mjs` | 只读体检，退出码可挂进脚本 |
| `lib/probe.mjs` | 抠函数与判定的实现（嵌套 / 提升两种布局都认） |
| `test/doctor.test.mjs` | 4 例断言：出厂必须报 pristine、已修必须报 patched、探针必须只读、认不出必须报错而不是给绿 |

`test/make-tree.mjs` 在临时目录里合成两种形状的假装机树，所以**测试不需要装 DSH**，仓库里也不放上游产物副本。

## 边界

- 只读：不写文件、不发网络请求、不碰会话存档、不读密钥。
- 读不出来就说读不出来（退出码 2），不会顺手打个"看着像"的补丁。
- 目前实证过的形状：`httpErrorCode`（0.1.5 线）与 `providerError`（0.1.7 线，会把判定链抠进同名壳子）。上游再改形状的话，工具会报错让你去看，而不是硬判。

## 关于补丁本身

打补丁的工具（`apply_dsh_patches.py` / `repatch.py` / `patches/` 清单）我先放在本机，没跟这个体检一起发出去。理由是它改的是厂商发布产物，需要每个人自己去判断要不要动 —— 而**判断依据**正是体检给出的那条：你的机器现在到底判成什么。
